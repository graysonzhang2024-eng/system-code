# 隐私同步与公开发布门禁

本系统把安全边界写进 Git 配置、可跟踪 hooks、同步代码和 CI，而不是依赖某次 Agent 对话记住。
真实路径、remote、token 和私人关键词只存在于本机 `.env` 或仓外文件。

## 三个仓的传输边界

| 仓库 | 自动行为 | 允许发布的位置 |
|---|---|---|
| `system-code` | 仅 `fetch` + `pull --ff-only` | 个人开发机手动 push |
| `work-vault` | 本地 commit；通过根、remote、私有可见性门禁后双向同步 | 已认证为 private 的预期 remote |
| `personal-vault` | 仅个人机本地读写和 commit | 不执行网络同步 |

`system-code` 的工作机安装会保留 fetch URL，同时把 push URL 设成不可用协议，并设置
`privacy.pushAllowed=false`。因此对话切换、重启和 Agent 忘记规则都不会恢复推送能力。

## 个人开发机安装

先在仓外准备私人 denylist（每行一个禁止进入公开仓的姓名、公司、项目、内部任务号等），再运行：

```bash
python3 scripts/install_privacy_guard.py \
  --machine personal \
  --denylist-file <outside-repository>/private-denylist.txt
python3 scripts/install_privacy_guard.py --machine personal --check
```

安装器幂等设置：

- `core.hooksPath=.githooks`；
- 公开仓匿名 noreply 提交身份；
- 仓外 denylist 路径与绑定的公开 remote；
- 个人机发布许可。

`pre-commit` 扫描真正的 index/staged snapshot、当前提交身份和已有历史；`pre-push` 读取 Git
传入的待推送 refs，扫描全部可达 commit、提交元数据、路径和历史 blobs。缺 denylist、remote
不一致、工作机发布或任一命中都会失败关闭。门禁不会打印私人命中词或原文。

## 工作机安装

```bash
python3 scripts/install_privacy_guard.py --machine work
python3 scripts/install_privacy_guard.py --machine work --check
```

这不会改变 fetch URL；框架仍可自动快进更新。push URL 会变为
`disabled://system-code-read-only`，且 pre-push 还有第二层拒绝。

## 私有 vault 网络保险

本机必须配置 `WORK_VAULT_PATH`，并通过 `.env` 的 `WORK_VAULT_EXPECTED_REMOTE` 或私仓本地 Git
配置绑定预期 remote。同步前会验证：

1. 配置路径、实际解析路径和 Git 顶层完全相同，且不是 `system-code`；
2. `origin` 与预期 remote 相同；
3. 网络 push 前，通过 GitHub API 认证得到 `private=true` 且 `visibility=private`。

私仓可见性只短期缓存六小时。token 缺失、认证失败、缓存过期或仓库不再 private 时，本地写入和
commit 保留，fetch/merge 可继续，但网络 push 暂停；浮窗显示高优先级安全警告。

预期 remote 也可以通过幂等安装命令绑定在私仓自己的本地 Git 配置中。绑定后本地 commit 可继续；
认证 private 检查未通过时命令返回警告且网络 push 仍暂停。token 可来自 `.env`，也可复用 Git
credential helper 中已有的凭据。

```bash
python3 scripts/install_vault_guard.py --work-vault <work-vault-path>
python3 scripts/install_vault_guard.py --personal-vault <personal-vault-path>
```

## 物理分仓启用与迁移

代码支持把生活/人际新记录直写 `personal-vault`，并让工作机拒绝此类创建。该行为由
`PERSONAL_VAULT_ROUTING=enabled` 开启。默认保持 `disabled`，因为启用前必须先备份并审计现有
共享仓中的私人记录；旧记录不会被代码静默搬迁。

在完成备份、展示迁移清单并得到用户单独确认前，系统仍只是显示层隐藏，不能声称已经物理隔离。

## CI 与远端设置

GitHub Actions 使用完整 checkout（`fetch-depth: 0`）运行通用全历史扫描和全量测试。私人 denylist
不进入公开 CI；它由本机 hooks 补足语义风险。把该 workflow 设为受保护分支的必需检查属于远端
仓库设置，需由仓库所有者单独确认和执行。
