# 开发接手指南

> 面向新的开发 Agent 和维护者。本文只包含公开、可迁移的信息；真实任务队列、账号、绝对路径
> 和原始开发史都留在私有工作区。

## 阅读顺序

1. `AGENTS.md`：开发边界与验收纪律。
2. `docs/管家手册.md`：业务角色、工具和 Agent 闭环。
3. `docs/系统全景.md`：当前架构与能力边界。
4. `docs/architecture.md`：设计取舍。
5. `docs/CHANGELOG.md`：匿名公开里程碑。

## 代码地图

```text
system-code/
├── system_os/             Python 工具、schema、同步与 Agent 授权
├── ui/                    Electron 浮窗与验收界面
├── tests/                 只使用临时目录或脱敏 fixtures 的 unittest
├── fixtures/              可公开假数据
├── schemas/               数据格式说明
├── docs/                  手册、全景、架构与公开 changelog
└── scripts/               发布前检查工具
```

关键模块：

- `system_os/actions.py`：Agent 和 UI 共用的高层业务动作。
- `system_os/executors.py`：专项执行器注册表和授权边界。
- `system_os/config.py`：读取本机 `.env`，不把部署值写死进代码。
- `system_os/vault.py`：Markdown + frontmatter CRUD。
- `system_os/sync.py`：数据同步、冲突保双份和代码快进更新。
- `system_os/os_api.py`：Electron 到 Python 的 JSON 桥。

## 开发流程

1. 先通过 actions 扫描私有开发队列，只推进已由用户批准的任务。
2. 修改前后检查状态，保护已有未提交内容。
3. 新功能至少包含实现、脱敏样例（适用时）和最小单测。
4. 运行 `python3 -m unittest discover -s tests`。
5. 运行 `python3 scripts/privacy_scan.py`；私有语义可通过仓外 denylist 补充检查。
   首次接管还必须按 `docs/隐私同步与发布.md` 安装并检查仓级 hooks；工作机安装为只拉取。
6. 在任务正文写清改动与验证结果，再提交用户验收。
7. 公开功能里程碑写入 `docs/CHANGELOG.md`；私有原始叙事不进本仓。

## 当前能力

- 任务、日志、日常、规划、决策、规则和知识库的数据模型。
- 任务树、今日待办、专注、常驻、打卡、验收和知识库浮窗。
- 多设备编号、自动同步、冲突保双份和分机每日记录。
- 通用专项 Agent 的提议、批准、决策、验收和用户接管闭环。
- 专项 Agent 的配置化授权根与仓外产物工作区。

## 已知边界

- 显示层过滤不是物理隔离；真正的生活隐私必须使用独立私有仓。
- UI 改动需要重载或重启 Electron；Python 动作通常由新进程即时加载。
- Agent 授权根来自被忽略的 `.env`；未配置时专项 Agent 不应获得全局权限。
- launchd plist 由安装脚本在本机生成，生成文件不得提交。
- 公开 fixtures 只能使用虚构对象，不能从真实 vault 复制后“稍作修改”。
- 公开发布与私有同步的持久门禁、换机步骤见 `docs/隐私同步与发布.md`。

## 安全上手

```bash
cd <workspace>/system-code
python3 -m unittest discover -s tests
python3 scripts/privacy_scan.py
```

需要运行 UI 时，先做静态和后台验证；确需打开窗口，放在屏幕边缘并在取证后立即关闭或最小化。
