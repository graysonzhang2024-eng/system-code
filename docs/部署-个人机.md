# 部署指南：个人机或新机器

> 目标：在新机器上拉起框架与私有数据仓。公开仓只提供通用步骤；远端地址、账号、真实路径和
> 业务授权根只写入本机配置。

## 1. 克隆仓库

分别克隆公开框架仓和你有权访问的私有数据仓。目录可以放在任意位置，不要求位于 home 下：

```bash
git clone <system-code-remote> <workspace>/system-code
git clone <work-vault-remote> <workspace>/work-vault
git clone <personal-vault-remote> <workspace>/personal-vault
```

`personal-vault` 只能部署到允许持有生活隐私的设备。

## 2. 配置本机 `.env`

```bash
cd <workspace>/system-code
cp .env.example .env
```

编辑被 Git 忽略的 `.env`：

```ini
MACHINE_ID=personal
WORK_VAULT_PATH=<workspace>/work-vault
PERSONAL_VAULT_PATH=<workspace>/personal-vault
INTERNSHIP_AGENT_ROOT_ID=<private-task-root-id>
INTERNSHIP_WORKSPACE_PATH=<workspace>/career-workspace
```

工作设备把 `MACHINE_ID` 设为 `work`，且不要克隆 `personal-vault`。专项 Agent 未启用时，
对应两项留空。

## 3. 安装依赖并验证

```bash
cd <workspace>/system-code
python3 -m pip install -r requirements.txt
python3 -m unittest discover -s tests

cd <workspace>/system-code/ui
npm install
npm start
```

## 4. 可选：macOS 开机自启

```bash
bash <workspace>/system-code/ui/autostart/install.sh
```

安装脚本会根据当前仓库位置生成 LaunchAgent plist。生成文件只留在本机，不提交到公开仓，
因此无需手工修改用户名或绝对路径。脚本直接使用 Electron.app 内的原生可执行文件，不依赖
launchd 的 PATH 查找 Node；若 Electron 尚未安装，会提示先在 `ui` 目录运行 `npm install`。

## 5. Agent 入口

- Codex 读取仓根 `AGENTS.md`。
- Claude Code 可读取兼容入口 `CLAUDE.md`。
- 业务角色与工具协议以 `docs/管家手册.md` 为准。
- 专项 Agent 的角色说明位于 `docs/agents/`，真实授权根来自本机 `.env`。

## 6. 同步边界

- `system-code` 只保存框架、匿名文档和脱敏 fixtures。
- `work-vault` 是私有数据仓，可按部署策略在多台设备间同步。
- `personal-vault` 是物理隔离的生活隐私仓，只能存在于受信设备。
- 数据写入后可自动提交和同步；冲突时保留双方版本，由用户或 Agent 人工合并。
- 框架代码更新只允许快进；本地有开发修改时自动跳过。

发布或推送公开仓前运行：

```bash
python3 scripts/privacy_scan.py
```
